- Toolchain: `moon 0.1.20261016 (1af328f 2026-10-16)`
- Method: `harness/bench` (release build) encodes and decodes fixed datasets, warming up once, sizing the repetition count for about 200 ms and then growing it until each timed round spans at least 20 ms, because the clock only resolves milliseconds; each figure is the median of 3 rounds. MB/s is computed against the PLAIN input size. Numbers are single-machine and not comparable across hosts, and a single round of the same binary still swings by 10-20% on the small cases, so compare toolchains or rewrites through medians, never through one run.
- Ratio is encoded bytes against PLAIN for the same column.
- A `ROARING+run_optimize` decode expands a 230-byte stream back into a million ids, so its decode MB/s is the rate ids come out, not the rate bytes are read; compare it with the ratio column, not alone.
- The `roaring-*` rows are a bitmap index, not a page encoding: `values` is the cardinality of the set, `plain` is the raw INT32 id stream it replaces (4 bytes per id, so MB/s is per input id byte), encode covers `from_ids` plus the serialization, and a `ROARING+run_optimize` row runs `run_optimize` before serializing.
